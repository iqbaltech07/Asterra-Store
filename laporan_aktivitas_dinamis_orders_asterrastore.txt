2. DAFTAR FILE YANG DIUBAH / DIBUAT
--------------------------------------------------------------------------------
1. frontend-user/src/lib/hooks/use-dynamic-orders.ts (File Baru)
   - Hook terisolasi untuk mengelola aktivitas dinamis frontend.
   - Konstanta durasi acak: MIN_PROCESSING_MS = 300.000 ms (5 menit) s.d.
     MAX_PROCESSING_MS = 480.000 ms (8 menit).
   - Menggunakan waktu sistem aktual (Date.now()) untuk menghitung elapsed time,
     bukan tick counter, sehingga kebal terhadap deviasi clock, throttling tab,
     maupun sleep/hibernasi perangkat.
   - Aturan mutlak 8 menit: jika elapsed >= 480.000 ms, status seketika menjadi 'completed' (Sukses).
   - Pembersihan interval aman (memory-leak proof) dengan isMounted guard dan clearInterval.
   - Mengambil kandidat aktivitas dari pesanan transaksi asli di database tanpa rekayasa data.

2. frontend-user/src/app/orders/page.tsx (File Dimodifikasi)
   - Mengintegrasikan hook useDynamicOrderActivities.
   - Label filter disesuaikan: 'completed' -> 'Sukses', 'processing' -> 'Processing'.
   - Badge status:
     * 'processing': badge berkedip (animate-pulse) dengan ikon faClock berputar (animate-spin)
       dan estimasi sisa waktu pemrosesan (Xm).
     * 'completed': badge hijau dengan faCircleCheck bertuliskan 'Sukses'.
   - Informasi kartu:
     * Saat status 'processing': indikator "Estimasi 5-8 Menit".
     * Saat status 'completed': indikator resmi "Garansi Resmi".
   - Integrasi Rekomendasi Produk & Promo Aktif:
     * Saat rawOrders.length === 0, menampilkan katalog produk digital resmi terpopuler
       menggunakan hook useCatalogProducts dan komponen ProductCard lengkap dengan promo aktif.

3. HASIL PENGUJIAN OTOMATIS (TEST SUITE)
--------------------------------------------------------------------------------
Skrip pengujian dieksekusi secara otomatis via Node.js v26.5.1:
scratch/test_dynamic_orders_scenarios.mjs

[TEST 1] Pengujian Rentang Durasi Acak (1.000 iterasi)
- Rentang durasi minimum: 300.000 ms (5 menit 0 detik)
- Rentang durasi maksimum: 480.000 ms (8 menit 0 detik)
- Hasil: 1.000/1.000 iterasi 100% berada di dalam rentang [300.000 ms, 480.000 ms].
- Status: PASS

[TEST 2] Transisi Status Processing -> Sukses
- t = 0s         : status 'processing', elapsed = 0s
- t = 180s (3m)  : status 'processing', remainingSeconds = 180s
- t = 359s (5m59s): status 'processing', remainingSeconds = 1s
- t = 360s (6m0s): durasi tercapai -> status berubah otomatis menjadi 'completed' (Sukses)
- Status: PASS

[TEST 3] Batas Mutlak Maksimum 8 Menit
- Aktivitas dengan durasi 8 menit (480.000 ms):
  * t = 479s: status 'processing'
  * t = 480s: status seketika menjadi 'completed' (Sukses)
- Aktivitas dengan durasi tidak valid/korup (misal 10 menit):
  * t = 480s + 1ms: pemotong mutlak MAX_PROCESSING_MS memaksa status menjadi 'completed' (Sukses).
  * Tidak ada aktivitas yang dapat berstatus 'processing' lebih dari 8 menit.
- Status: PASS

[TEST 4] Penanganan Pesanan Database Lama yang Berstatus Processing
- Pesanan lama di database yang berstatus 'processing' lebih dari 8 menit sejak order_date
  secara otomatis ditampilkan sebagai 'completed' (Sukses) pada antarmuka publik.
- Status: PASS

[TEST 5] Ketahanan Waktu Sistem (System Clock Reliance)
- Simulasi tab masuk background / sleep laptop selama beberapa menit:
  * Begitu waktu sistem Date.now() melewati ambang batas durasi, transisi status
    langsung terjadi tanpa bergantung pada jumlah eksekusi interval setInterval.
- Status: PASS

[TEST 6] Pembaruan Waktu Relatif (formatRelativeTime)
- 30 detik lalu -> "Baru saja"
- 2 menit lalu  -> "2 menit lalu"
- 1 jam lalu    -> "1 jam lalu"
- 1 hari lalu   -> "1 hari lalu"
- Status: PASS
